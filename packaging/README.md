# Packaging

Manifests for the three package managers squish targets. They are generated by
[`render.sh`](render.sh), which reads the version from `Cargo.toml` and pulls
each checksum from the `.sha256` file the release workflow attaches:

```bash
./packaging/render.sh          # the version in Cargo.toml
./packaging/render.sh 0.2.0    # a specific release
```

Run it after a release finishes uploading, commit the result, then publish.
A checksum of all zeroes means that asset was not on the release yet.

> **Nothing here is published yet.** squish has no release, so no bucket, tap or
> winget entry exists. These are ready to submit the moment there is one.

## Scoop

[`scoop/squish.json`](scoop/squish.json) belongs in a bucket repository —
`MkSavin/scoop-bucket`, with the manifest at `bucket/squish.json`:

```powershell
scoop bucket add mksavin https://github.com/MkSavin/scoop-bucket
scoop install squish
```

The manifest carries `checkver` and `autoupdate`, so `scoop-update.ps1` picks up
later releases and re-reads the checksum from the release itself. After the first
publish, this file mostly maintains itself.

## Homebrew

[`homebrew/squish.rb`](homebrew/squish.rb) belongs in a tap —
`MkSavin/homebrew-squish`, with the formula at `Formula/squish.rb`:

```bash
brew install MkSavin/squish/squish
```

It covers macOS arm64 and Linux x64, which is what the release builds.

## winget

The three files in [`winget/`](winget) go to
[microsoft/winget-pkgs](https://github.com/microsoft/winget-pkgs) as a pull
request, under `manifests/m/MkSavin/Squish/<version>/`:

```powershell
winget install MkSavin.Squish
```

Validate before opening the PR:

```powershell
winget validate --manifest packaging/winget
```

The archive holds the binary in a versioned folder, which is why the manifest
uses `NestedInstallerFiles` with the full relative path. `render.sh` keeps that
path in step with the version.

## ffmpeg

All three declare ffmpeg as a dependency where the package manager has a notion
of one (scoop, Homebrew). winget has no dependency model for portable packages,
so the requirement is stated in the description instead.
